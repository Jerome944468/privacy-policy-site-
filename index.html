Semantic Search Ranking
About Privacy Policy

Search results ranked by meaning, not just matching words.

This research project builds a search ranking system that reads a query the way a person means it. It blends classic keyword scoring with Sentence-BERT, then uses a trained classifier to judge how relevant each result really is.

The problem it solves

Keyword search needs the same words in the query and in the listing. Someone who types “device for pointing and clicking” never typed “mouse”, so a keyword engine has almost nothing to match.

On our paraphrased test queries, TF-IDF keyword search scored an NDCG@5 of 0.25, while semantic search scored 0.62.

How it works

  1. Read the querySentence-BERT converts the query, and every record in the catalogue, into 384 numbers. Records with similar meaning end up with similar numbers.
  2. Find close matchesAn exact cosine-similarity search (FAISS) finds the nearest records. TF-IDF and BM25 add keyword evidence, and the three scores are blended into one hybrid score.
  3. Judge relevanceA compact neural network we trained rates each query and result pair as not relevant, somewhat relevant or highly relevant, and reports how confident it is.
  4. Rank the listResults are ordered so the best match sits first. Precision@5 and NDCG@5 measure how well that works.

What it searches

Two datasets: 13,388 product listings, and statistics for 167 countries such as income, child mortality and life expectancy. Each dataset has its own search index.

The relevance classifier reached about 90% test accuracy on a held-out 20% of 1,150 labelled query and product pairs.

Semantic search is the clear gain over keyword search. The hybrid performs about the same as semantic search on this small benchmark, so we do not claim it is better.

These figures come from the team’s own benchmark of 10 paraphrased queries, and the relevance labels were generated by a rule-based method. Read them as evidence that the approach works on this data, not as a guarantee elsewhere.

Privacy Policy

How the semantic search ranking system handles information. Last updated October 2026.

The short version

  • The system has no accounts and does not ask for your name, email or any personal details.
  • A search query is used only to produce ranked results.
  • Nothing is sold, shared for advertising, or used to track you.

1Overview

This policy covers the semantic search ranking system described on the About page. It is a search and ranking component built as an academic research project. It has no sign-in, profiles or user interface of its own: it receives a search query from whichever application uses it and returns a ranked list of results.

2Information the system processes

Search queries
The text typed into a search box, sent to the system so it can rank results.
Catalogue data
The product listings and country statistics the system searches. They contain product names, categories and country-level indicators, not personal information.
Relevance scores
The scores and labels the system calculates for each result.

3Information it does not collect

Names, email addresses, passwords, phone numbers, payment details, precise location, contacts, photos, or access to a device’s camera or microphone.

4How information is used

A query is converted into numbers with Sentence-BERT, compared with the catalogue, and scored using keyword methods (TF-IDF and BM25) and a trained relevance classifier. The ranked list goes back to the application that asked. Queries are not used for advertising, profiling or sale.

5Where processing happens

The language model, search index and classifier run inside the system’s own service. Model files are downloaded when the service is set up; queries are not sent to an outside AI provider to produce results.

6Logs and retention

The system is designed not to keep a history of search queries. The server or hosting platform that runs the service may record routine technical details, such as the time of a request and the network address it came from, for troubleshooting and security. The team does not use these records to identify or profile anyone.

The catalogue data and trained model files are kept for the life of the project.

7Security

The project’s security test plan covers:

  • Cleaning search input against injection and script attacks
  • Rejecting empty, oversized or malformed requests
  • Rate limits to prevent abuse and scraping
  • Generic error messages that reveal no internal details
  • Encrypted HTTPS connections when the service is deployed
  • Checks that the model files have not been tampered with

8Open-source components

Sentence-BERT (all-MiniLM-L6-v2) creates the text embeddings, FAISS performs similarity search, scikit-learn provides TF-IDF, rank_bm25 provides BM25 scoring, and TensorFlow with Keras runs the relevance classifier. They run as libraries inside the service.

9Use inside other applications

This system is meant to be built into other applications. Those applications manage their own accounts, sign-in and data, and their own privacy policies apply to that information. Read them alongside this one.

10Children

The system is built for academic, business and research use and is not directed at children. It does not knowingly collect personal information from anyone, including children under 13.

11Your choices

Because the system does not collect personal information, there is normally nothing to access, correct or delete. If you think a query or other information was recorded, contact the team and we will look into it.

12Changes to this policy

We may update this policy as the system changes. The date at the top of this page shows when it last changed.
